\chapter{METODOLOGI PENELITIAN}

\section{Jenis Penelitian}
Jenis penelitian ini adalah penelitian rekayasa perangkat lunak (\textit{software engineering research}) yang bersifat terapan. Fokus utama penelitian adalah merancang, mengimplementasikan, dan mengevaluasi penambahan dukungan protokol FINS (\textit{Factory Interface Network Service}) pada sistem SCADA open-source FUXA. 

Pendekatan penelitian menggunakan metode \textbf{mixed-method}:  
\begin{itemize}
    \item \textbf{Kuantitatif:} Pengukuran performa komunikasi (latensi baca/tulis, \textit{throughput}, persentase keberhasilan, serta penggunaan CPU/memori). Berdasarkan literatur, performa FINS/UDP dapat mencapai latensi rata-rata 3--10 ms untuk \textit{polling} 100--200 tag dalam kondisi jaringan normal, lebih cepat dibandingkan Modbus TCP yang berkisar 20--40 ms pada beban serupa. Data ini menjadi acuan target performa. 
    \item \textbf{Kualitatif:} Observasi kemudahan konfigurasi parameter, usability antarmuka FUXA, serta feedback dari pengguna/operator terkait pengalaman penggunaan sistem.
\end{itemize}

Pendekatan ini dipilih agar hasil penelitian valid secara teknis sekaligus relevan dalam konteks kebutuhan pengguna industri.

\section{Metode Pengembangan Sistem}
Metode pengembangan perangkat lunak yang digunakan adalah \textbf{iterative prototyping}, dengan siklus berulang analisis kebutuhan, perancangan, implementasi, pengujian, dan evaluasi. 

\begin{enumerate}
    \item \textbf{Analisis Kebutuhan:} Identifikasi parameter komunikasi FINS (DA1, SA1, Unit Address), kebutuhan polling, penulisan nilai ke PLC, serta fitur DAQ dan alarm.
    \item \textbf{Perancangan Sistem:} Penyusunan arsitektur konektor FINS pada sisi server (Node.js) dan antarmuka pengguna pada sisi client (Angular). Disertai diagram arsitektur dan \textit{sequence diagram} komunikasi FINS.
    \item \textbf{Implementasi:} Pengembangan modul konektor FINS pada \texttt{server/runtime/devices/fins}, komponen konfigurasi tag/perangkat (Angular), serta logika polling dan penulisan data.
    \item \textbf{Pengujian:} Uji fungsional, integrasi, serta evaluasi performa dengan monitoring paket menggunakan Wireshark dan skrip benchmarking.
    \item \textbf{Evaluasi dan Perbaikan:} Identifikasi bug, optimasi performa polling, pencegahan \textit{memory leak}, serta peningkatan fitur DAQ dan alarm berdasarkan hasil pengujian.
\end{enumerate}

\section{Metode Pengujian}
Pengujian mencakup pengujian fungsional (\textit{black-box}), struktural (\textit{white-box}), serta evaluasi performa.

\subsection{Black-Box Testing}
\begin{itemize}
    \item \textbf{Konfigurasi:} Uji penyimpanan dan pemanggilan parameter (DA1, SA1, Unit Address, protocol).
    \item \textbf{Baca/Tulis Data:} Verifikasi polling nilai PLC dan penulisan tag melalui UI.
    \item \textbf{Alarm:} Validasi pemicu alarm dan notifikasi.
    \item \textbf{DAQ:} Uji penyimpanan dan pemanggilan data historis.
    \item \textbf{UI:} Penggunaan antarmuka tanpa error.
\end{itemize}

\subsection{White-Box Testing}
\begin{itemize}
    \item \textbf{Unit Testing Konektor:} Fungsi \texttt{connect()}, \texttt{read()}, \texttt{write()}, \texttt{poll()}.
    \item \textbf{Event Handling:} Uji pembersihan listener untuk mencegah \textit{memory leak}.
    \item \textbf{Error Handling:} Simulasi kegagalan komunikasi dan mekanisme retry.
    \item \textbf{Traffic Analysis:} Validasi paket FINS dengan Wireshark sesuai spesifikasi protokol.
    \item \textbf{Integrasi Client-Server:} Penelusuran alur data dari UI (Angular) ke backend Node.js.
\end{itemize}

\subsection{Metrik Evaluasi}
\begin{itemize}
    \item Latensi baca/tulis rata-rata (ms) serta distribusi (min, max, p95).
    \item \textit{Throughput} (operasi/detik).
    \item Persentase keberhasilan komunikasi (\% sukses).

    \item Waktu deteksi alarm (ms).
    \item Akurasi timestamp DAQ.
\end{itemize}
