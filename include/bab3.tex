\section{Tahapan Penelitian}
Tahapan penelitian dijalankan secara iteratif dengan pendekatan \textit{iterative prototyping}, yaitu siklus berulang antara analisis, desain, implementasi, pengujian, dan evaluasi. Diagram alir (flowchart) tahapan penelitian disajikan pada Gambar \ref{fig:flowchart-tahapan}.

    \includegraphics[height=0.75\textwidth]{images/flowchart-tahapan.png}
    \caption{Flowchart Tahapan Penelitian}
    \label{fig:flowchart-tahapan}
\end{figure}

Tahapan rinci penelitian adalah sebagai berikut:

\begin{enumerate}
    \item \textbf{Studi literatur dan perumusan requirement}\\
    Mengumpulkan referensi teknis terkait protokol FINS, arsitektur HMI berbasis web (khususnya FUXA), serta praktik pengujian komunikasi PLC. 
    Hasil: dokumen requirement fungsional dan non-fungsional.
    
    \item \textbf{Uji coba pustaka \texttt{omron-fins} di Node.js}\\
    Membuat skrip sederhana (\texttt{Communication test .js}) untuk menguji apakah pustaka dapat terkoneksi dengan PLC Omron, melakukan operasi baca, dan menulis nilai ke alamat tertentu. 
    Hasil: validasi awal apakah pustaka berfungsi dengan PLC target.

    \item \textbf{Analisis kebutuhan dan spesifikasi sistem}\\
    Identifikasi kebutuhan integrasi ke HMI: parameter FINS (SA1, DA1, alamat memori, protokol UDP/TCP), kebutuhan alarm, tampilan status, dan kebutuhan UI. 
    Hasil: spesifikasi teknis dan use-case.

    \item \textbf{Perancangan arsitektur dan desain detail}\\
    Mendesain arsitektur frontend (Angular) untuk form konfigurasi perangkat, backend (Node.js) untuk modul FINS, serta jalur komunikasi antara keduanya. 
    Hasil: diagram arsitektur dan desain skema komunikasi.

    \item \textbf{Implementasi prototipe HMI}\\
    Integrasi pustaka \texttt{omron-fins} ke dalam modul HMI terbuka FUXA, meliputi koneksi, baca/tulis, polling, alarm, serta tampilan nilai pada UI. 
    Hasil: prototipe fungsional HMI dengan dukungan FINS.

    \item \textbf{Pengujian fungsional dan integrasi}\\
    Melakukan uji baca/tulis tag, verifikasi tampilan nilai dan status pada UI, serta analisis paket jaringan menggunakan Wireshark untuk memastikan framing FINS benar. 
    Hasil: laporan bug dan perbaikan iteratif.

    \item \textbf{Pengujian performa sederhana}\\
    Menjalankan skenario pengujian dengan jumlah tag dan interval polling berbeda untuk mengukur keterlambatan respon, tingkat keberhasilan, dan ketahanan koneksi. 
    Hasil: dataset pengujian (CSV, log) dan metrik evaluasi.

    \item \textbf{Analisis data dan evaluasi}\\
    Mengolah hasil pengujian untuk menilai ketercapaian tujuan: konektivitas, kemudahan konfigurasi, kejelasan tampilan HMI, dan keandalan koneksi. 
    Hasil: analisis dan rekomendasi optimasi.

    \item \textbf{Penyempurnaan dan dokumentasi}\\
    Menyempurnakan implementasi berdasarkan hasil evaluasi, menyusun dokumentasi penggunaan modul, panduan konfigurasi, serta publikasi kode pada repositori (mis. GitHub). 
    Hasil: rilis final modul dan panduan.
\end{enumerate}

Pada setiap iterasi siklus di atas, dilakukan evaluasi risiko teknis (mis. \textit{timeout}, \textit{connection error}), mitigasi, dan pencatatan perubahan versi. Tahapan ini memastikan bahwa integrasi FINS pada HMI yang dikembangkan tidak hanya berfungsi secara fungsional tetapi juga andal (reliable) dan terdokumentasi.

\section{Modifikasi UI (Frontend Angular)}
Modifikasi antarmuka pengguna dilakukan pada sisi \textit{frontend} berbasis Angular dengan menambahkan komponen khusus untuk konfigurasi FINS. 
Perubahan utama antara lain:
\begin{itemize}
    \item Penambahan \texttt{TagPropertyEditFinsComponent} untuk mengatur parameter FINS seperti \texttt{DA1}, \texttt{SA1}, \texttt{Unit Address}, dan protokol (UDP/TCP).
    \item Integrasi Angular Material untuk tampilan form konfigurasi agar konsisten dengan protokol lain (misalnya Modbus).
    \item Penyesuaian \texttt{DevicePropertyComponent} agar parameter FINS dapat disimpan, ditampilkan ulang, dan diedit.
    \item Validasi input (misalnya alamat PLC hanya menerima nilai numerik dalam rentang tertentu).
\end{itemize}

\section{Modifikasi Backend (Node.js Konektor FINS)}
Modifikasi sisi \textit{backend} dilakukan dengan menambahkan modul baru di dalam folder 
\texttt{server/runtime/devices/fins}. Perubahan meliputi:
\begin{itemize}
    \item Implementasi fungsi dasar koneksi PLC:
    \begin{itemize}
        \item \texttt{connect()} untuk inisialisasi komunikasi FINS.
        \item \texttt{read()} untuk membaca nilai alamat PLC.
        \item \texttt{write()} untuk menulis nilai ke alamat PLC.
        \item \texttt{poll()} untuk melakukan polling berkala.
    \end{itemize}
    \item Mekanisme \texttt{retry} jika koneksi terputus atau terjadi \textit{timeout}.
    \item Pengaturan logging error agar memudahkan debugging.
    \item Integrasi dengan lapisan API internal FUXA agar UI dapat berinteraksi langsung dengan modul FINS.
\end{itemize}

\section{Metode Pengujian}
Pengujian mencakup pengujian fungsional (\textit{black-box}), struktural (\textit{white-box}), serta evaluasi performa.

\subsection{Black-Box Testing}
\begin{itemize}
    \item \textbf{Konfigurasi:} Uji penyimpanan dan pemanggilan parameter (DA1, SA1, Unit Address, protocol).
    \item \textbf{Baca/Tulis Data:} Verifikasi polling nilai PLC dan penulisan tag melalui UI.
    \item \textbf{Alarm:} Validasi pemicu alarm dan notifikasi.
    %\item \textbf{DAQ:} Uji penyimpanan dan pemanggilan data historis.
    \item \textbf{UI:} Penggunaan antarmuka tanpa error.
\end{itemize}

\subsection{White-Box Testing}
\begin{itemize}
    \item \textbf{Unit Testing Konektor:} Fungsi \texttt{connect()}, \texttt{read()}, \texttt{write()}, \texttt{poll()}.
    \item \textbf{Event Handling:} Uji pembersihan listener untuk mencegah \textit{memory leak}.
    \item \textbf{Error Handling:} Simulasi kegagalan komunikasi dan mekanisme retry.
    \item \textbf{Traffic Analysis:} Validasi paket FINS dengan Wireshark sesuai spesifikasi protokol.
    \item \textbf{Integrasi Client-Server:} Penelusuran alur data dari UI (Angular) ke backend Node.js.
\end{itemize}
